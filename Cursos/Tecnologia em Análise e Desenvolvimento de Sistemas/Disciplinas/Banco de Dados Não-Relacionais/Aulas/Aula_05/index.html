Redis na Prática: Padrão Cache-Aside, Performance e Expiração (TTL)

Estudo de caso prático do e-commerce ShopGrids: descubra como eliminar gargalos de consultas repetidas no banco de dados implementando o padrão Cache-Aside com Redis (GET, SET e SETEX) e resolva o problema da inconsistência de dados através do TTL (Time To Live).

1. O Problema Real: "Categorias em Destaque" no E-Commerce ShopGrids

Imagine que você trabalha no e-commerce ShopGrids. Na página inicial existe a seção Categorias em Destaque (/categories/featured). O banco de dados relacional possui centenas de categorias, mas o time de Marketing escolhe apenas algumas para destacar na semana (WHERE is_featured = true).

❌ Sem Cache (O Gargalo na Black Friday):
  • Cada cliente que abre a Home dispara um SELECT no banco de dados.
  • O banco relacional precisa lidar com ACID, índices, bloqueios e limite de conexões.
  • Com milhares de acessos simultâneos buscando exatamente os mesmos dados, o banco cria fila, dá Timeout e derruba a aplicação.
✅ Com Padrão Cache-Aside (Redis + TTL):
  • A API consulta primeiro o Redis (Memória RAM) em ~100 ns.
  • Apenas a 1ª requisição vai ao banco SQL e salva uma cópia no Redis com SETEX (TTL de 20s).
  • Todas as milhares de requisições seguintes recebem a resposta direto da memória RAM sem tocar no banco!
Camada 1: Disco Magnético

~10 ms

Leitura mecânica em HD tradicional (milissegundos).

Camada 2: Query SQL Básica

~1 ms a 80 ms

Operação em banco relacional com overhead de transação.

Camada 3: Leitura SSD

~100 µs

Armazenamento em estado sólido (microssegundos).

Camada 4: Memória RAM (Redis)

~100 ns

Nanossegundos + Protocolo binário RESP ultra-rápido!

2. Os 3 Critérios de Ouro: Quando Usar (e Quando NÃO Usar) Cache?

A memória RAM do servidor é finita e cara. Antes de colocar qualquer dado no Redis, valide se ele atende simultaneamente a estas 3 regras apresentadas no vídeo:

1. Dado Muito Requisitado

Precisa ter alto volume de leituras repetidas (ex.: Categorias em destaque na Home do e-commerce).

2. Muda com Pouca Frequência

Não faz sentido cachear um dado que muda a cada segundo. Categorias em destaque mudam semanalmente ou mensalmente.

3. Tolera Consistência Eventual

Pode ter um pequeno delay de atualização (TTL). Nunca coloque saldo bancário/Pix em cache com TTL!

3 Passo 3: Criando o Banco de Dados Relacional (criar_banco.py)

O que fazer: Criar o arquivo criar_banco.py para gerar o banco SQLite shopgrids.db com a tabela categories contendo 6 categorias (4 inicialmente marcadas com is_featured = 1). 

# Arquivo: criar_banco.py
# Importa a biblioteca nativa do Python para banco de dados SQLite
import sqlite3

# Função que cria a tabela 'categories' e insere os registros iniciais
def inicializar_banco():
    # Conecta ao arquivo 'shopgrids.db' (cria o arquivo no disco caso não exista)
    conn = sqlite3.connect("shopgrids.db")
    # Cria o cursor para executar comandos SQL
    cursor = conn.cursor()
    # Apaga a tabela caso já exista de um teste anterior
    cursor.execute("DROP TABLE IF EXISTS categories")
    # Cria a tabela 'categories' (is_featured: 1 = Em Destaque, 0 = Oculta)
    cursor.execute("""
        CREATE TABLE categories (
            id INTEGER PRIMARY KEY,
            name TEXT NOT NULL,
            image TEXT NOT NULL,
            is_featured INTEGER NOT NULL DEFAULT 0
        )
    """)
    # Lista com 6 categorias: as 4 primeiras com is_featured=1 e as 2 de inverno com is_featured=0
    categorias = [
        (1, "TV & Áudio", "tv-audio.png", 1),
        (2, "Desktop & Laptop", "laptop.png", 1),
        (3, "Smartphones", "smartphone.png", 1),
        (4, "Acessórios Gamer", "gamer.png", 1),
        (5, "Moda Inverno", "inverno.png", 0),
        (6, "Aquecedores", "aquecedor.png", 0),
    ]
    # Insere todas as 6 categorias na tabela em lote
    cursor.executemany("INSERT INTO categories VALUES (?, ?, ?, ?)", categorias)
    # Grava as alterações no disco e fecha a conexão
    conn.commit()
    conn.close()
    print("✓ Banco 'shopgrids.db' criado com sucesso com 6 categorias (4 em destaque)!")

if __name__ == "__main__":
    inicializar_banco()
# Executando no terminal: $ python criar_banco.py
✓ Banco 'shopgrids.db' criado com sucesso com 6 categorias (4 em destaque)!
4 Passo 4: Versão 1 do app.py — Sem Cache (Consultando Direto no Banco SQL)

Cenário: Criamos a 1ª versão do app.py onde toda chamada em GET /categories/featured faz o SELECT no banco SQLite, mais duas rotas auxiliares para simularmos a equipe de Produto mudando os destaques no banco. 

# Arquivo: app.py (VERSÃO 1 - SEM CACHE)
import sqlite3                      # Driver SQLite nativo
import time                         # Para medir latência e simular I/O de disco
from flask import Flask, jsonify    # Microframework web Flask

app = Flask(__name__)               # Instancia o servidor Flask

def buscar_categorias_no_banco():
    time.sleep(0.08)                # Simula 80ms de leitura em disco no banco relacional
    conn = sqlite3.connect("shopgrids.db")
    conn.row_factory = sqlite3.Row  # Permite converter cada linha do SQL em dicionário
    cursor = conn.cursor()
    # Filtra apenas as categorias marcadas como destaque (is_featured = 1)
    cursor.execute("SELECT id, name, image, is_featured FROM categories WHERE is_featured = 1")
    categorias = [dict(row) for row in cursor.fetchall()]
    conn.close()
    return categorias

@app.route("/categories/featured", methods=["GET"])
def get_featured_categories():
    inicio = time.time()                        # Marca o início da requisição
    categorias = buscar_categorias_no_banco()   # GARGALO: Vai ao banco SQL em toda chamada!
    tempo_ms = round((time.time() - inicio) * 1000, 2)
    return jsonify({
        "origem": "BANCO_DE_DADOS (SQL)",
        "tempo_ms": tempo_ms,
        "total": len(categorias),
        "dados": categorias
    })

# Rota auxiliar: simula o time de Produto deixando apenas 2 categorias de inverno no banco SQL
@app.route("/categories/inverno", methods=["POST"])
def ativar_categorias_inverno():
    conn = sqlite3.connect("shopgrids.db")
    conn.execute("UPDATE categories SET is_featured = 0")
    conn.execute("UPDATE categories SET is_featured = 1 WHERE id IN (5, 6)")
    conn.commit()
    conn.close()
    return jsonify({"mensagem": "Banco SQL atualizado: apenas 2 categorias de inverno em destaque!"})

# Rota auxiliar: simula o time de Produto ativando todas as 6 categorias para a Black Friday
@app.route("/categories/blackfriday", methods=["POST"])
def ativar_todas_categorias():
    conn = sqlite3.connect("shopgrids.db")
    conn.execute("UPDATE categories SET is_featured = 1")
    conn.commit()
    conn.close()
    return jsonify({"mensagem": "Banco SQL atualizado: todas as 6 categorias em destaque!"})

if __name__ == "__main__":
    app.run(port=5000, debug=True)  # Sobe a API na porta 5000 com auto-reload
# Terminal 1: python app.py | Terminal 2: $ curl -s http://localhost:5000/categories/featured | jq '{origem, tempo_ms, total}'
{ "origem": "BANCO_DE_DADOS (SQL)", "tempo_ms": 81.45, "total": 4 }
5 Passo 5: Versão 2 do app.py — Implementando o Cache-Aside Básico (GET e SET)

Evolução do código: Importamos json e redis, consultamos r.get("featured_categories") antes de bater no banco SQL e salvamos uma cópia com r.set() usando json.dumps(). 

# Alteração na rota /categories/featured (Versão 2 do app.py):
import json   # Para converter lista em String JSON (dumps) e String em lista (loads)
import redis  # Cliente oficial do Redis

# Conecta ao Redis na porta 6379 convertendo respostas de bytes para String automaticamente
r = redis.Redis(host="localhost", port=6379, db=0, decode_responses=True)

@app.route("/categories/featured", methods=["GET"])
def get_featured_categories():
    inicio = time.time()
    cache_key = "featured_categories"               # Nome da chave no Redis

    # 1. Consulta o Redis primeiro (Memória RAM)
    cached_categories = r.get(cache_key)
    if cached_categories:                           # CACHE HIT: Encontrou no Redis!
        tempo_ms = round((time.time() - inicio) * 1000, 2)
        dados = json.loads(cached_categories)       # Converte de String JSON para lista Python
        return jsonify({
            "origem": "CACHE_REDIS (Memória RAM)",  # Nem encostou no banco SQL!
            "tempo_ms": tempo_ms,
            "total": len(dados),
            "dados": dados
        })

    # 2. Se não encontrou no Redis (CACHE MISS), busca no Banco SQL
    categorias = buscar_categorias_no_banco()
    # 3. Salva uma cópia no Redis em formato String JSON (porém sem expiração ainda!)
    r.set(cache_key, json.dumps(categorias))

    tempo_ms = round((time.time() - inicio) * 1000, 2)
    return jsonify({
        "origem": "BANCO_DE_DADOS (SQL)",
        "tempo_ms": tempo_ms,
        "total": len(categorias),
        "dados": categorias
    })
# Testando 1ª Chamada (Cache Miss) vs 2ª Chamada (Cache Hit): 1ª Chamada: { "origem": "BANCO_DE_DADOS (SQL)", "tempo_ms": 82.10, "total": 4 }
2ª Chamada: { "origem": "CACHE_REDIS (Memória RAM)", "tempo_ms": 0.42, "total": 4 }
6 Passo 6: Reproduzindo o Problema da Inconsistência (Dados Defasados no Cache)

A Pegadinha: Atualizamos o banco SQL para deixar apenas as 2 categorias de inverno em destaque. Mas como usamos r.set() sem expiração, a API continua devolvendo as 4 categorias antigas para sempre!

# 1. Atualiza o banco SQL para ter apenas 2 categorias de inverno: $ curl -s -X POST http://localhost:5000/categories/inverno | jq .
# 2. Consulta a API novamente: $ curl -s http://localhost:5000/categories/featured | jq '{origem, total}'
{ "origem": "CACHE_REDIS (Memória RAM)", "total": 4 } <-- ERRO: Continua trazendo 4 em vez de 2!
7 Passo 7: Versão 3 Final — A Solução com Invalidação por Tempo (SETEX com TTL de 20s)

Solução Definitiva: Trocamos r.set() por r.setex(cache_key, 20, json.dumps(categorias)), apagamos a chave infinita anterior (redis-cli DEL featured_categories) e fazemos o teste ao vivo de 20 segundos! 

# No lugar de r.set(cache_key, json.dumps(categorias)), colocamos:
r.setex(cache_key, 20, json.dumps(categorias))  # TTL = 20 segundos de vida útil na memória RAM
# 1. Apaga a chave antiga sem TTL e faz a 1ª consulta (grava as 2 de inverno por 20s): $ redis-cli DEL featured_categories
$ curl -s http://localhost:5000/categories/featured | jq '{origem, total, ttl_segundos}'
{ "origem": "BANCO_DE_DADOS (SQL)", "total": 2, "ttl_segundos": 20 }

# 2. Ativa todas as 6 categorias no banco (Black Friday) e fica consultando: $ curl -s -X POST http://localhost:5000/categories/blackfriday
$ curl -s http://localhost:5000/categories/featured | jq '{origem, total, ttl_segundos}'
>> Enquanto ttl_segundos > 0 retorna total: 2 (do cache). Assim que passam os 20s, expira sozinho e atualiza para total: 6!

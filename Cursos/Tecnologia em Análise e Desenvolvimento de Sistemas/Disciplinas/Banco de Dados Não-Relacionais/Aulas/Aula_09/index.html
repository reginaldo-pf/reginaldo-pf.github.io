Teorema CAP (Brewer, 2000)

Em redes não-confiáveis, falhas de partição (P) são inevitáveis. Portanto, o sistema deve escolher entre Consistência Estrita (CP) ou Disponibilidade Contínua (AP).

  • • CP (ex.: MongoDB): Sob partição, bloqueia leituras/escritas em nós isolados para prevenir dados divergentes.
  • • AP (ex.: Cassandra): Mantém todas as réplicas aceitando escritas, convergindo via consistência eventual.

Teorema PACELC (Abadi, 2012)

Analisa o comportamento tanto sob partição quanto em regime normal:

Se [P]artição: [A]vailability vs [C]onsistency;
[E]lse: [L]atency vs [C]onsistency.

O MongoDB classifica-se tipicamente como PC/EC (prioriza consistência), enquanto o Redis opera como PA/EL (prioriza latência em RAM).

Padrão Cache-Aside com Invalidação (Python)

Coordenação explícita de leitura no Redis com expiração (TTL) e invalidação atômica em alterações de estoque. 

def buscar_com_cache(r, db, sku: str, ttl: int = 60):
    chave = f"produto:{sku}"
    cached = r.get(chave)
    if cached:
        return json.loads(cached), "CACHE_HIT"

    doc = db.produtos.find_one({"sku": sku})
    if doc:
        doc["_id"] = str(doc["_id"])
        r.setex(chave, ttl, json.dumps(doc))
        return doc, "CACHE_MISS"
    return None, "NOT_FOUND"

def alterar_estoque(r, db, sku: str, delta: int):
    # Atualização atômica no banco primário
    res = db.produtos.update_one({"sku": sku}, {"$inc": {"estoque": delta}})
    if res.modified_count > 0:
        # Invalidação imediata para evitar dados obsoletos
        r.delete(f"produto:{sku}")
        return True
    return False

Medição de Latência: Redis vs MongoDB Indexado vs COLLSCAN

Comprovando na prática as ordens de magnitude de velocidade entre o cache residente em memória RAM (<0.1 ms), o acesso com árvore balanceada B-Tree (~1 ms) e a varredura linear completa em disco (>18 ms).

Os 5 Grandes Desafios Práticos do Simulado N1

Desafio 1: Cache-Aside com Fallback e TTL

Implementar consulta de produto verificando primeiro o Redis (produto:{sku}) e hidratando a chave com 60 segundos de expiração caso venha do MongoDB.

Desafio 2: Invalidação de Cache e Atualização Atômica

Executar mutação atômica com $inc no MongoDB e apagar imediatamente a chave no Redis para impedir leituras inconsistentes.

Desafio 3: Carrinho em Hashes do Redis

Manipular chave carrinho:{cliente_id} com o comando HINCRBY e renovação de expiração de 20 minutos.

Desafio 4: Criação de Índice ESR

Criar índice composto na coleção pedidos seguindo estritamente a sequência Equality (status), Sort (data_pedido) e Range (valor_total).

Desafio 5: Pipeline Analítico de Vendas

Montar agregação com $match, $unwind e $group para calcular o faturamento por categoria de produto.

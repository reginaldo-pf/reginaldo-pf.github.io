JSON vs. BSON (Binary JSON) e Anatomia do ObjectId

Limitações do JSON Puro em Disco

  • • Travessia Lenta: Exige ler caractere por caractere para localizar um campo interno.
  • • Erro Financeiro (IEEE 754): Em float binário comum, 0.1 + 0.2 = 0.30000000000000004.
  • • Pobreza de Tipos: Sem distinção nativa para inteiros de 32/64 bits, datas UTC ou decimais exatos.

Vantagens do BSON no Motor WiredTiger

  • • Prefixos de Tamanho: Cada campo inclui seu tamanho em bytes no cabeçalho, permitindo salto direto $\mathcal{O}(1)$.
  • • Decimal128 (NumberDecimal): Precisão decimal exata para valores monetários.
  • • Limite Físico: Até 16 MB por documento BSON e 100 níveis de aninhamento.
4 Bytes (Timestamp)

671ec880

Segundos desde 01/01/1970. Ordenar por _id já ordena por data de criação.

5 Bytes (Host/Processo)

a1b2c3d4e5

Identificador aleatório único por máquina/processo, evitando colisão.

3 Bytes (Contador)

f60001

Contador incremental atômico para documentos gerados no mesmo segundo.

Questões de Revisão

1. Por que o MongoDB utiliza BSON em vez de JSON puro e por que devemos usar Decimal128 para preços?

O BSON adiciona prefixos de tamanho binários que permitem ao motor WiredTiger saltar campos sem precisar fazer parsing de texto, além de fornecer tipos nativos como ObjectId, ISODate e Decimal128. O tipo Decimal128 evita erros de arredondamento de ponto flutuante binário IEEE 754 (0.1 + 0.2 = 0.30000000000000004).

2. Qual é o risco de usar um Unbounded Array (Array Ilimitado) e como o Subset Pattern resolve isso?

Um array que cresce sem limite degrada a escrita no WiredTiger (realocação em disco) e pode estourar o limite físico de 16 MB por documento BSON. O Subset Pattern mantém apenas os itens mais recentes embutidos no documento principal e salva o histórico completo em uma coleção separada referenciada.

3. Por que a coleção de pedidos aplica o Snapshot Pattern nos itens comprados?

Se o pedido guardar apenas a referência produto_id, qualquer reajuste futuro no preço do produto na coleção produtos alterará retroativamente o valor de pedidos passados. Congelar sku, nome e preco_unit dentro do pedido preserva a integridade histórica.

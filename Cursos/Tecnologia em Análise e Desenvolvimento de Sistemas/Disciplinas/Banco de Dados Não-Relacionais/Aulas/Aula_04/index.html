Operações Avançadas via redis-cli no Terminal

Comandos fundamentais explicados parâmetro por parâmetro com casos de uso de mercado.

1. Variações do Comando SET

SET <chave> <valor> [EX segundos] [PX ms] Expiração TTL

Grava a chave e agenda sua autodestruição após o tempo determinado. Evita acúmulo desnecessário na memória RAM.

127.0.0.1:6379> SET busca:termo:notebook_dell "[{id:101,nome:'Dell'}]" EX 300
OK
127.0.0.1:6379> TTL busca:termo:notebook_dell
(integer) 298
SET <chave> <valor> NX EX <segundos> Distributed Lock (Trava)

Not eXists: Só define se a chave ainda NÃO existir. Essencial para controle de concorrência e compras na Black Friday.

# Worker 1 adquire o lock do estoque:
127.0.0.1:6379> SET lock:estoque:prod_500 "worker_A" NX EX 15
OK
# Worker 2 tenta concorrer simultaneamente:
127.0.0.1:6379> SET lock:estoque:prod_500 "worker_B" NX EX 15
(nil)  # Bloqueado com seguranca!
SET <chave> <valor> KEEPTTL Preservação de TTL

Atualiza o payload sem reiniciar a contagem regressiva de expiração original.

127.0.0.1:6379> SET sessao:user_99 "jwt_token_v1" EX 60
OK
127.0.0.1:6379> SET sessao:user_99 "jwt_token_v2_renovado" KEEPTTL
OK
127.0.0.1:6379> TTL sessao:user_99
(integer) 58  # O contador regressivo continua sem interrupcoes!

2. Variações do Comando GET

GETDEL <chave> Consumo Atômico de Uso Único

Obtém o valor e deleta a chave na mesma instrução atômica. Ideal para códigos de verificação em 2 etapas (2FA), vouchers e tokens de PIX.

127.0.0.1:6379> SET token:pix:transacao_101 "AUTORIZADO_R$500" EX 60
OK
127.0.0.1:6379> GETDEL token:pix:transacao_101
"AUTORIZADO_R$500"
127.0.0.1:6379> GET token:pix:transacao_101
(nil)  # Chave consumida e destruida sem risco de reuso!
MGET <chave1> <chave2> ... Batch em 1 RTT

Recupera múltiplas chaves em uma única viagem de rede (*Round-Trip Time*), eliminando gargalos de I/O de sockets.

127.0.0.1:6379> MGET moeda:usd_brl moeda:eur_brl moeda:btc_brl
1) "5.45"
2) "5.95"
3) "345000.00"

Arquitetura em Memória e Persistência em Disco

Entenda por que a RAM é volátil e como o Redis grava cópias duráveis sem perder velocidade.

1. RDB (Snapshotting Pontual)

Tira uma "foto" binária compactada da memória e grava no arquivo dump.rdb.

  • SAVE: Bloqueia todo o servidor até salvar. Nunca use em produção!
  • BGSAVE: Assíncrono via fork() com Copy-on-Write do Linux. Não trava clientes.
  • Trade-off: Risco de perder os dados gravados após o último snapshot.
# Configuracao no redis.conf:
save 900 1      # 15 min se 1 chave mudou
save 300 10     # 5 min se 10 mudaram
save 60 10000   # 1 min se 10k mudaram

# No terminal:
127.0.0.1:6379> BGSAVE
Background saving started
127.0.0.1:6379> LASTSAVE
(integer) 1791888929
2. AOF (Append-Only File Log)

Registra todas as operações de escrita em sequência contínua no arquivo appendonly.aof.

  • appendfsync everysec: Padrão da indústria. Perda máxima de 1 segundo de dados.
  • BGREWRITEAOF: Compacta o histórico eliminando instruções redundantes.
  • Persistência Híbrida: Cabeçalho em RDB e cauda em AOF (aof-use-rdb-preamble yes).
# Configuracao no redis.conf:
appendonly yes
appendfilename "appendonly.aof"
appendfsync everysec

# No terminal:
127.0.0.1:6379> BGREWRITEAOF
Background append only file rewriting started
127.0.0.1:6379> INFO persistence

Guia de Instalação no Windows via WSL 2

Por que o Redis não possui executável Windows nativo e como rodá-lo perfeitamente com Linux no WSL 2.

ℹ️ Por que usar o WSL 2? O Redis utiliza chamadas exclusivas do kernel Linux (epoll para I/O multiplexado e fork() com Copy-on-Write para snapshots sem travamento). O WSL 2 oferece o kernel Linux real dentro do Windows sem peso de máquina virtual tradicional.

Passo 1: Instalar o Ubuntu no PowerShell

Abra o PowerShell como Administrador e execute:

wsl --install -d Ubuntu

Passo 2: Instalar o Redis no Ubuntu WSL

Abra o terminal Ubuntu que foi instalado e rode:

sudo apt update && sudo apt install redis-server -y
sudo service redis-server start
redis-cli ping
# Resposta: PONG

Passo 3: Conectar ferramentas do Windows

O WSL 2 faz o roteamento automático de portas para o host Windows! Você pode baixar o Redis Insight para Windows e conectar diretamente em localhost:6379.

Modernização: Redis como Camada de Contexto para IA

"Context is all you need" — Entenda como o modelo Chave-Valor acelera Agentes e corta custos de LLMs.

LangCache: Cache de Prompts

Modelos de linguagem como Gemini e GPT custam caro a cada token processado. Em produção, 40 a 80% das requisições corporativas são idênticas ou quase duplicadas. O LangCache intercepta esses prompts no Redis e responde em menos de 100 ms com custo zero de API!

Agent Memory: Memória Cross-Session

LLMs são stateless por definição. Toda chamada começa "fria". Utilizando Hashes e Lists no Redis com TTLs longos ou persistência AOF, os agentes autônomos retêm memórias e fatos do usuário ao longo de múltiplos turnos e sessões sem perder contexto.

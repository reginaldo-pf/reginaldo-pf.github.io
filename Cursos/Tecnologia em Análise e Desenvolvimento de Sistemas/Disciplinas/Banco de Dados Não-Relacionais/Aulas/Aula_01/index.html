1. O Desafio dos Dados e as Limitações do Modelo Relacional

Por mais de três décadas (desde Edgar F. Codd em 1970), o modelo relacional e a linguagem SQL reinaram absolutos no desenvolvimento de software corporativo. No entanto, o advento da Web 2.0 e do Big Data impôs novas demandas aos sistemas de armazenamento:

  • Volume Massivo & Concorrência: Milhões de acessos simultâneos ao redor do planeta.
  • Escalabilidade Horizontal (Scale-Out): Em vez de adquirir servidores cada vez maiores e mais caros (Scale-Up), a computação moderna distribui os dados por dezenas ou centenas de nós em cluster.
  • Custo Computacional dos JOINs: Executar junções complexas entre tabelas gigantescas distribuídas em rede é uma operação de altíssimo custo e latência.
  • Descasamento de Impedância Objeto-Relacional: O atrito permanente entre o paradigma de objetos na aplicação e as tabelas rígidas do banco.
In [1]: Definição do Domínio em Python (Dataclasses) 
from dataclasses import dataclass, field
from typing import List

@dataclass
class ItemPedido:
    produto: str
    quantidade: int
    preco_unitario: float

@dataclass
class Pedido:
    id_pedido: str
    data_emissao: str
    itens: List[ItemPedido] = field(default_factory=list)

    @property
    def total(self) -> float:
        return sum(item.quantidade * item.preco_unitario for item in self.itens)

@dataclass
class Cliente:
    id_cliente: int
    nome: str
    email: str
    cidade: str
    uf: str
    pedidos: List[Pedido] = field(default_factory=list)

print("✅ Modelo de domínio carregado com sucesso!")

2. Comparativo: Fragmentação Normalizada vs Agregação JSON

Observe a diferença entre a abordagem normalizada do SQL (que espalha uma única entidade em múltiplas linhas e tabelas) e a abordagem agregada do NoSQL orientado a documentos (que guarda a entidade completa como um agregado de acesso instantâneo):

In [2]: Abordagem SQL Relacional (Necessidade de Múltiplos JOINs) 
-- Para remontar o cliente com seus pedidos e itens no modelo relacional:
SELECT 
    c.id, c.nome, c.email, 
    p.id AS pedido_id, p.data_emissao, 
    i.produto, i.quantidade, i.preco_unitario
FROM clientes c
JOIN pedidos p ON p.cliente_id = c.id
JOIN itens_pedido i ON i.pedido_id = p.id
WHERE c.id = 1;

Mapeamento Lógico Relacional (Parte 1): Entidades Fortes, Fracas e Relacionamentos 1:1 e 1:N

Compreenda a conversão determinística e formal de um Diagrama Entidade-Relacionamento (DER) para o Esquema Lógico Relacional fundamentado nas regras de Elmasri & Navathe e Heuser: Primeira Forma Normal (1FN), achatamento de atributos compostos, omissão de derivados, chave primária composta em entidades fracas, as 3 abordagens de mapeamento 1:1 e a regra fundamental do 1:N com integridade referencial.

Visão Geral: Onde Estamos no Projeto de Banco de Dados?

Após validarmos o minimundo no Modelo Conceitual (DER de Peter Chen e Heuser) nas Aulas 04 a 08 e estabelecermos o rigor formal do Modelo Relacional de Codd na Aula 09, entramos na fase de Mapeamento Lógico. O Algoritmo de 7 Passos de Elmasri & Navathe assegura uma conversão determinística e sem perda de semântica.

Passo 1

Entidades Fortes

Passo 2

Entidades Fracas

Relacionamentos 1:1

3 abordagens técnicas: FK no lado total com AK, Fusão ou Referência Cruzada.

Relacionamentos 1:N

Regra de ouro: PK do lado 1 migra como FK para o lado N (e recursivos).

1 Passo 1: Mapeamento de Entidades Regulares (Fortes)

Para cada tipo de entidade regular (forte) $E$ no DER, cria-se uma relação $R$ que contém todos os atributos simples de $E$. Escolhe-se uma das chaves de $E$ como Chave Primária ($\underline{PK}$) de $R$.

Achatamento (Flattening) de Compostos

Para preservar a Primeira Forma Normal (1FN), atributos compostos (ex: endereco) são desmembrados em seus subatributos atômicos simples (logradouro, numero, bairro, cep). O nome agrupador não vira coluna.

Omissão de Atributos Derivados

Atributos derivados (ex: idade calculada a partir de data_nasc) são omitidos do esquema lógico armazenado para evitar redundância e inconsistência por atualização temporal.

// DER: PACIENTE(id_paciente, cpf, nome_completo(prim_nome, sobrenome), data_nasc, /idade)
PACIENTE ( id_paciente, cpf [AK], prim_nome, sobrenome, data_nasc )

2 Passo 2: Mapeamento de Entidades Fracas e Relacionamentos Identificadores

Para cada entidade fraca $W$ associada a uma proprietária forte $E$, cria-se uma relação $R_W$. Incluem-se todos os atributos simples de $W$, propaga-se a $\underline{PK_E}$ como Chave Estrangeira ($FK$) em $R_W$, e forma-se a Chave Primária Composta:

PK(R_W) = { FK(PK_E) ∪ Discriminador_Parcial(W) }
// OLT (Forte) e PORTA_PON (Fraca com discriminador num_porta)
OLT ( id_olt, nome_olt, ip_gerencia )
PORTA_PON ( id_olt_fk, num_porta, potencia_dbm, status )
PORTA_PON.id_olt_fk REFERENCES OLT.id_olt [NOT NULL]

3 Passo 3: As 3 Estratégias Técnicas para Relacionamentos Binários 1:1

A escolha da estratégia depende estritamente das restrições de participação $(min, max)$ para evitar proliferação de valores NULL:

Abordagem A: FK no Lado Total

Participação (0,1) : (1,1)

Propaga-se a PK do lado parcial para a relação do lado total como FK com restrição de unicidade (AK).

Garante 0% de NULL na coluna FK.

Abordagem B: Fusão em Relação Única

Participação (1,1) : (1,1)

Funde-se as duas entidades em uma única relação com todos os atributos.

Elimina a necessidade de JOINs frequentes.

Abordagem C: Relação Cruzada

Participação (0,1) : (0,1) Esparsa

Cria-se uma relação intermediária com as PKs de ambas as entidades quando o vínculo ocorre raramente.

Evita tabelas com 90%+ de NULL.

4 Passo 4: Relacionamentos Binários 1:N e Auto-Relacionamentos Recursivos

A Regra de Ouro do 1:N: Propaga-se sempre a Chave Primária ($\underline{PK}$) do lado 1 como Chave Estrangeira ($FK$) na relação do lado N ($FK_{\text{lado } N} \longrightarrow PK_{\text{lado } 1}$).

Por que o sentido inverso é proibido? Se colocássemos a chave do lado $N$ dentro do lado $1$, uma única tupla do lado $1$ precisaria armazenar múltiplos identificadores (ex: array de chaves), o que viola formalmente a Primeira Forma Normal (1FN) que exige atributos atômicos!
// Relacionamento 1:N Regular: POP_REGIONAL (1) ---> (N) ROTEADOR_BORDA
POP_REGIONAL ( cod_pop, nome_cidade, capacidade_gbps )
ROTEADOR_BORDA ( id_roteador, modelo, ip_loopback, cod_pop_fk )
// Auto-Relacionamento 1:N: TECNICO supervisiona outros TECNICOS
TECNICO ( matricula, nome_tecnico, especialidade, mat_supervisor_fk )
TECNICO.mat_supervisor_fk REFERENCES TECNICO.matricula [NULLABLE]

Exercícios de Fixação e Modelagem Lógica

Exercício 1 — Passo 1: Entidade Forte, Achatamento e Derivados (ASSINANTE)

Enunciado: A entidade regular ASSINANTE possui id_assinante (PK), cpf (identificador alternativo único), nome_completo (composto por primeiro_nome e sobrenome), endereco_instalacao (composto por logradouro, numero, bairro, cep), data_adesao e tempo_fidelidade_meses (derivado).

ASSINANTE ( id_assinante, cpf [AK], primeiro_nome, sobrenome, logradouro, numero, bairro, cep, data_adesao )

Justificativa Formal: O achatamento decompõe atributos compostos em atômicos, atendendo à Primeira Forma Normal (1FN). O atributo derivado tempo_fidelidade_meses é omitido do esquema armazenado para evitar anomalias de atualização temporal (calculado via consulta SQL).

Exercício 2 — Passo 2: Cadeia de Entidades Fracas (2 Níveis: PREDIO → SALA → RACK)

Esquemas Resultantes:

PREDIO ( cod_predio, nome_predio )
SALA_TECNICA ( cod_predio_fk, num_sala, area_m2 )
RACK ( cod_predio_fk, num_sala_fk, num_rack, altura_u )

A Chave Primária de RACK é composta por 3 atributos: as chaves estrangeiras acumuladas da hierarquia proprietária mais o seu discriminador local.

Exercício 3 — Passo 3: Decisão Técnica em Relacionamentos 1:1
  • Caso 1: TECNICO (0,1) : (1,1) VEICULO: Aplica-se a Abordagem A inserindo mat_tecnico_fk na relação VEICULO com restrição UNIQUE (AK) e NOT NULL. Evita 75% de valores NULL que ocorreriam se a FK fosse em TECNICO.
  • Caso 2: ORDEM_SERVICO (1,1) : (1,1) LAUDO: Aplica-se a Abordagem B (Fusão) em uma única relação ORDEM_SERVICO_COMPLETA, eliminando overhead de JOINs obrigatórios síncronos.
  • Caso 3: FUNCIONARIO (0,1) : (0,1) VAGA_VIP (Esparsa): Aplica-se a Abordagem C (Relação Cruzada) criando OCUPACAO_VAGA_VIP(id_func_fk [AK], num_vaga_fk [AK], andar) para evitar 98% de NULL nas tabelas principais.
Exercício 4 — Passo 4: Relacionamento 1:N Regular vs. Recursivo

São criadas exatamente 2 relações:

EQUIPE_MANUTENCAO ( cod_equipe, nome_equipe, turno )
AGENTE_SUPORTE ( matricula, nome_agente, nivel_certificacao, data_lotacao, cod_equipe_fk, mat_coordenador_fk )

Propagar a chave de AGENTE_SUPORTE para EQUIPE_MANUTENCAO violaria a 1FN, pois exigiria armazenar um vetor/lista de agentes em uma única célula.

Exercício 5 — Desafio Integrador: Monitoramento de Enlaces de Rádio Micro-ondas

Esquema Relacional Completo:

TORRE ( id_torre, nome_torre, latitude, longitude, altitude_m )
LICENCA_ANATEL ( num_licenca, data_vencimento, orgao_emissor, id_torre_fk [AK, NOT NULL] )
ANTENA_PARABOLICA ( id_torre_fk, num_sequencial_antena, diametro_m, frequencia_ghz, azimute_graus )

Combina Passo 1 (achatamento de coordenadas em TORRE), Passo 3 Abordagem A (FK em LICENCA com AK e NOT NULL) e Passos 2/4 (ANTENA como entidade fraca identificada por TORRE).

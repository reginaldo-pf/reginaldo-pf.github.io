A Dualidade: Álgebra (Procedural) vs. Cálculo (Declarativo)

A ciência dos bancos de dados apoia-se em duas linguagens formais complementares concebidas por Edgar F. Codd:

Álgebra Relacional (Procedural)
Especifica o "COMO" obter

Recebe relações como argumento e aplica uma sequência prescrita de operações encadeadas ($\sigma, \pi, \bowtie$). Usada internamente no motor de execução.

πnome(σcidade='Tauá'(CLIENTE))
Cálculo Relacional (Declarativo)
Especifica o "O QUE" obter

Define o conjunto-verdade de predicados lógicos de Primeira Ordem sem estipular a ordem de acesso em disco. Inspirou diretamente o padrão SQL.

{ t[nome] | t ∈ CLIENTE ∧ t[cidade] = 'Tauá' }
Variáveis de Tupla { t | P(t) }

Cálculo Relacional de Tuplas (CRT)

A variável livre $t$ representa uma tupla completa. Átomos relacionam pertinência ($t \in R$), comparação de atributos ($t[A] \ \theta \ s[B]$) e constantes.

Quantificador Existencial (∃): Usado para ligar chaves primárias e estrangeiras declarativamente.
Quantificador Universal (∀): Usado para modelar consultas universais ("para todo").
Variáveis de Domínio { ⟨x1..xn⟩ | P }

Cálculo Relacional de Domínios (CRD)

As variáveis assumem valores individuais sobre o domínio de atributos em vez de tuplas inteiras. Inspirou diretamente o QBE (Query By Example) da IBM.

Mapeamento Posicional: Variáveis alinham-se diretamente com as colunas da relação.
Interface Visual (QBE): O usuário digita valores de exemplo diretamente em grades na tela.

Segurança de Expressões e o Domínio da Fórmula (DOM)

Na lógica pura, a expressão $\{ t \mid \neg(t \in \text{CLIENTE}) \}$ é sintaticamente válida, mas geraria uma relação infinita no computador.

Regra de Segurança de Codd

Uma expressão no Cálculo é dita Segura se e somente se todos os valores de suas tuplas resultantes forem obrigatoriamente extraídos de DOM(ψ) (conjunto finito formado pelas constantes explícitas da consulta somadas aos valores existentes nas tabelas referenciadas).

Otimizador de Consultas (Query Optimizer) & Árvores Relacionais

Quando uma instrução SQL é submetida, o SGBD a converte em uma árvore canônica inicial e aplica regras de equivalência algébrica para minimizar leituras em disco e tabelas temporárias em RAM.

Desafio 1 • Tradução Formal Tripla

Clientes de Tauá com Compras Acima de R$ 400

Recupere o nome e a cidade dos clientes de Tauá com compras de valor superior a R$ 400,00 nas três linguagens formais.

// 1. Álgebra Relacional:
πnome, cidade(σcidade='Tauá' ∧ valor > 400(CLIENTE ⋈ PEDIDO))
// 2. Cálculo Relacional de Tuplas (CRT):
{ t | ∃c ∈ CLIENTE (c[cidade]='Tauá' ∧ t[nome]=c[nome] ∧ ∃p ∈ PEDIDO (p[id_cli]=c[id_cli] ∧ p[valor]>400)) }
// 3. SQL Padrão:
SELECT c.nome, c.cidade FROM CLIENTE c JOIN PEDIDO p ON c.id_cli = p.id_cli WHERE c.cidade = 'Tauá' AND p.valor > 400;
Desafio 2 • Quantificação Universal e Leis de De Morgan

Clientes que Compraram Todos os Livros Baratos

Encontre os clientes que compraram todos os livros com preço inferior a R$ 30,00.

// Forma Universal (∀):
{ c[nome] | c ∈ CLIENTE ∧ ∀l ∈ LIVRO (l[preco] < 30 → ∃p ∈ PEDIDO (p[id_cli]=c[id_cli] ∧ p[isbn]=l[isbn])) }
// Forma Existencial (∃ via De Morgan - base do NOT EXISTS no SQL):
{ c[nome] | c ∈ CLIENTE ∧ ¬∃l ∈ LIVRO (l[preco] < 30 ∧ ¬∃p ∈ PEDIDO (p[id_cli]=c[id_cli] ∧ p[isbn]=l[isbn])) }
Desafio 3 • Diagnóstico de Segurança Formal

Correção de Expressão Insegura

A consulta { t | ¬(t ∈ PEDIDO) ∧ t[valor] > 100 } é insegura porque o conjunto de tuplas do universo que satisfazem a negação é infinito.

// Expressão Segura Equivalente: todos os valores provêm obrigatoriamente de DOM(ψ)
{ c[id_cli, nome] | c ∈ CLIENTE ∧ ¬∃p ∈ PEDIDO (p[id_cli]=c[id_cli] ∧ p[valor] > 100) }

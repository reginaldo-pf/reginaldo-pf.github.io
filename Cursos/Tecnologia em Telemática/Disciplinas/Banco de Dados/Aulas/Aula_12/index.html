O Princípio Inviolável do Fechamento Relacional (Closure)

Na formulação formal de Edgar F. Codd (1970), a Álgebra Relacional opera estritamente sobre relações (conjuntos matemáticos de tuplas). A propriedade de Fechamento Relacional estabelece que o resultado de qualquer operação algébrica é obrigatoriamente uma nova relação bem formada.

Relação(ões) de Entrada → [ Operador Algébrico ] → Nova Relação Válida (Esquema + Tuplas)
Viabiliza Aninhamento Arbitrário

Operador Unário σ

Seleção de Tuplas (σ)

Filtro horizontal de linhas baseado em condição booleana p. Mantém o mesmo esquema e todas as colunas, filtrando apenas as linhas.

σp(R) = { t ∈ R | p(t) = VERDADEIRO }
  • Grau: Inalterado (grau mantido: grau(R))
  • Cardinalidade: 0 ≤ k ≤ |R|
  • Comutativo: σp1(σp2(R)) ≡ σp2(σp1(R))
Exemplo Didático: σpreco < 60 ∧ ano ≥ 2019(LIVRO) → Retorna L04 e L06 (2 tuplas).
Operador Unário π

Projeção de Atributos (π)

Filtro vertical de colunas especificadas na lista L. Regra de ouro: elimina automaticamente tuplas duplicadas na saída.

πL(R) = { t[L] | t ∈ R }
  • Grau: Reduzido ao tamanho da lista (|L| colunas)
  • Deduplicação: Mandatória por ser conjunto matemático estrito
  • Cascata: πL1(πL2(R)) ≡ πL1(R)
Exemplo Didático: πcategoria(LIVRO) → Retorna {Computacao, Literatura, Exatas} (3 tuplas).
Operador Unário ρ

Renomeação (ρ)

Atribui novos nomes a relações ou a atributos individuais. Essencial para desambiguar atributos homônimos em junções e autorrelacionamentos.

ρS(B1, B2, ..., Bn)(R)
  • ρS(R): Renomeia apenas a relação
  • ρ(B1..Bn)(R): Renomeia apenas os atributos
  • Grau e Cardinalidade: Permanecem rigorosamente intactos
Exemplo Didático: ρOBRA(cod, nome, cat, ano, val)(LIVRO) → Renomeia a relação e suas 5 colunas.
Operador Binário ∪

União (∪)

Combina todas as tuplas presentes em R, em S ou em ambas. Exige Compatibilidade de União (mesmo grau e domínios pareados compatíveis).

R ∪ S = { t | t ∈ R ∨ t ∈ S }
  • Compatibilidade: grau(R) = grau(S) = n e domínios compatíveis
  • Deduplicação: Tuplas repetidas aparecem uma única vez
  • Comutativo: R ∪ S ≡ S ∪ R
Exemplo Didático: LEITOR_LOCAL ∪ LEITOR_EXTERNO → Lista unificada de todos os leitores cadastrados.
Operador Binário −

Diferença de Conjuntos (−)

Retorna as tuplas que pertencem a R e não pertencem a S. Operação assimétrica não comutativa (R − S ≠ S − R).

R − S = { t | t ∈ R ∧ t ∉ S }
  • Compatibilidade: Exige mesma aridade e domínios pareados
  • Não comutativo: R − S ≠ S − R
  • Uso canônico: Identificar ausências ("quem fez X mas nunca fez Y")
Exemplo Didático: πid_cli(CLIENTE) − πid_cli_fk(PEDIDO) → Clientes cadastrados que nunca compraram.
Operador Binário ×

Produto Cartesiano (×)

Combina todas as tuplas de R com todas as tuplas de S. Não requer compatibilidade de união. Base matemática do operador de Junção.

R × S = { t1 · t2 | t1 ∈ R ∧ t2 ∈ S }
  • Grau Resultante: grau(R) + grau(S) (soma)
  • Cardinalidade: |R| × |S| tuplas geradas
  • Fundamento da Junção: σFK = PK(R × S) ≡ R ⋈ S
Exemplo Didático: CURSO (2 tuplas) × TURNO (2 tuplas) → 4 tuplas combinadas com 4 atributos.

Quadro Sinóptico dos 6 Operadores Fundamentais da Álgebra Relacional

Operador Símbolo Sintaxe Canônica Aridade Efeito no Grau (Colunas) Efeito na Cardinalidade (Linhas)
Seleção σ σp(R) Unário Inalterado (= grau(R)) Filtrado (0 ≤ k ≤ |R|)
Projeção π πL(R) Unário Reduzido (= |L|) Reduzido / Igual (≤ |R|) com deduplicação
Renomeação ρ ρS(B1..Bn)(R) Unário Inalterado (= grau(R)) Inalterado (= |R|)
União ∪ R ∪ S Binário Inalterado (Exige compatibilidade: grau n) Máximo |R| + |S| (elimina duplicatas)
Diferença − R − S Binário Inalterado (Exige compatibilidade: grau n) Mínimo 0, Máximo |R|
Produto Cartesiano × R × S Binário Soma (grau(R) + grau(S)) Multiplicação (|R| × |S|)

O que é uma Árvore de Consulta Relacional (Query Tree)?

Uma Árvore de Consulta é uma estrutura em grafo acíclico dirigida que representa visualmente a sequência procedural de avaliação de uma consulta relacional:

1. Nós Folha (Base)

Representam as relações físicas armazenadas em disco (tabelas base do catálogo).

2. Nós Internos

Representam os operadores algébricos intermediários (σ, π, ×, ∪, −).

3. Nó Raiz (Topo)

Representa a relação final entregue ao usuário ou à aplicação.

Estrutura em Árvore: Avaliação Bottom-Up

Consulta: "Recuperar o título e preço dos livros de Literatura com preço menor que R$ 50,00".

π titulo, preco
Nó Raiz (Resultado Final)
σ categoria = 'Literatura' ∧ preco < 50
Nó Interno (Filtragem de Linhas)
LIVRO (Relação Base)
Nó Folha (6 tuplas em disco)

Heurística: "Empurrar Seleções para Baixo"

O Query Optimizer dos SGBDs utiliza leis de equivalência algébrica para reorganizar a árvore antes da execução física.

Plano Ingênuo (Sem Otimização)
σcond(CLIENTE × PEDIDO)

Gera primeiro todas as 10.000 × 100.000 = 1.000.000.000 (1 bilhão) tuplas do produto cartesiano para depois filtrar em memória RAM (alto custo de I/O!).

Plano Otimizado (Push-Down Selection)
(σcidade = 'Taua'(CLIENTE)) × (σano = 2026(PEDIDO))

Filtra cada relação individualmente antes de cruzar. Reduz os operandos para 20 clientes e 50 pedidos, gerando apenas 1.000 combinações controladas.

Desafio Prático 1 • Seleção Composta & Projeção

Consulta Acadêmica em ALUNO

Dada a relação ALUNO(id_aluno, nome, curso, cr, cidade), formule uma expressão da álgebra relacional que recupere o nome e o CR de todos os discentes de 'Administracao' que residem em 'Taua' com CR ≥ 8.5.

// Resolução Modular em Etapas:
PASSO1 ← σcurso = 'Administracao' ∧ cidade = 'Taua' ∧ cr ≥ 8.5(ALUNO)
RESULTADO ← πnome, cr(PASSO1)
// Expressão Aninhada em Linha Única:
πnome, cr(σcurso = 'Administracao' ∧ cidade = 'Taua' ∧ cr ≥ 8.5(ALUNO))
Desafio Prático 2 • Diferença de Conjuntos

Detecção de Clientes Inativos via Subtração

A partir das relações CLIENTE(id_cli, nome, cidade) e PEDIDO(id_ped, id_cli_fk, data, valor), encontre o código e nome dos clientes que NUNCA realizaram nenhuma compra registrada.

// 1. Isolar todos os códigos de clientes:
TODOS_IDS ← πid_cli(CLIENTE)
// 2. Isolar os códigos que aparecem em pedidos:
COMPRADORES ← πid_cli_fk(PEDIDO)
// 3. Subtração de conjuntos compatíveis:
INATIVOS ← TODOS_IDS − COMPRADORES
// 4. Recuperar os nomes através de cruzamento:
RESULTADO ← πid_cli, nome(σCLIENTE.id_cli = INATIVOS.id_cli(CLIENTE × INATIVOS))
Desafio Prático 3 • Produto Cartesiano e Junção Manual

Associação de Produto e Categoria

Sem utilizar o operador avançado de Junção (⋈), associe PRODUTO(id_prod, nome_prod, id_cat_fk) com CATEGORIA(id_cat, nome_cat) gerando uma listagem com nome_prod e nome_cat.

// Concatenação e filtragem por chave referencial:
TEMP1 ← PRODUTO × CATEGORIA
TEMP2 ← σPRODUTO.id_cat_fk = CATEGORIA.id_cat(TEMP1)
RESULTADO ← πnome_prod, nome_cat(TEMP2)
Desafio Prático 4 • Padronização com Renomeação (ρ) e União (∪)

Relatório Unificado de Contatos Acadêmicos

Considere as tabelas DOCENTE(id_doc, nome, email) e MONITOR(id_mon, nome_estudante, email_acad). Gere uma relação unificada contendo nome e email de ambos.

// 1. Projetar colunas homólogas:
D ← πnome, email(DOCENTE)
M ← πnome_estudante, email_acad(MONITOR)
// 2. Renomear para compatibilidade de esquema:
M_PADRAO ← ρ(nome, email)(M)
// 3. União de conjuntos compatíveis:
RESULTADO ← D ∪ M_PADRAO
